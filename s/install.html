Installation

pg-laya is a PostgreSQL extension plus a companion model server. make install does both: it copies the extension into your server and installs Ollaya (a single binary that serves the Laya decision models) as a system service on the same machine.

ⓘ

Managed hosts that withhold superuser or plpython3u (Supabase, Neon, RDS/Aurora, …) cannot run pg-laya. Docker is the easiest way to try it without touching a host.

With an AI agent (easiest)

The repo ships an agent skill. Install it into your project and tell Claude Code, Codex, Cursor or any skill-aware agent to finish the job:

bash
npx skills add realZachi/pg-laya

Then simply say:

> Install pglaya on this server and set it up.

The agent runs a preflight (Postgres version, plpython3u, superuser), installs the extension and the model server, runs CREATE EXTENSION laya CASCADE, and runs a smoke test.

From PGXN

bash
pgxn install laya                 # pinned: pgxn install laya --ref 0.3.0
psql -d mydb -c "CREATE EXTENSION laya CASCADE;"

From source (PGXS)

bash
git clone https://github.com/nyimbi/pg-laya && cd pg-laya
make install                      # also installs the Ollaya model server as a service
psql -d mydb -c "CREATE EXTENSION laya CASCADE;"
ⓘ

There is nothing to compile — PGXS just copies laya.control and sql/laya--*.sql into the extension directory that pg_config points at. Use make install PG_CONFIG=/path/to/pg_config to target a specific server, and NO_SERVE=1 make install to skip the model server (containers, CI, or when it runs elsewhere).

Docker

bash
docker build -t pg-laya .
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=pw pg-laya
psql -h 127.0.0.1 -U postgres -d postgres -c "CREATE EXTENSION laya CASCADE;"

The container runs no service manager, so the model server runs outside it. Point the extension at it: SET laya.api_url = 'http://<server-host>:11435/v1/systemone';

The Ollaya model server

make install installs Ollaya and starts it on http://127.0.0.1:11435 (where the default laya.api_url points), as a systemd unit ollaya on Linux or a launchd agent com.pglaya.ollaya on macOS. It then pulls the laya model — a router over laya:en / laya:multilingual, ~1.5 GB, sha256-verified, resumable. Models load on first use and stay warm for OLLAYA_KEEP_ALIVE (default 5 minutes).

TaskLinux (systemd)macOS (launchd)
Statussystemctl status ollayalaunchctl list | grep com.pglaya.ollaya
Logsjournalctl -u ollaya -ftail -f ~/Library/Logs/ollaya.serve.err.log
Restartsudo systemctl restart ollayalaunchctl kickstart -k gui/$(id -u)/com.pglaya.ollaya

Modelsollaya list · ollaya ps · ollaya show laya:en

Server environment (set at install time, passed to the service): OLLAYA_HOST (127.0.0.1:11435), OLLAYA_API_KEY (off), OLLAYA_DEVICE (auto), OLLAYA_KEEP_ALIVE (5m). Re-run OLLAYA_…=… make install-serve to change any of them.

API key (optional)

None by default. If you enable auth on the server (OLLAYA_API_KEY=secret make install-serve), give the extension the same token:

sql
SET laya.api_key = 'secret';                  -- this session
ALTER ROLE analyst SET laya.api_key = 'secret'; -- persistent for a role

Verify

bash
psql -d mydb -f scripts/smoke_test.sql

It creates a temp table, runs each function once, and prints laya_stats() so you can see requests, tokens and estimated cost.
