Changelog

All notable changes. The format follows Keep a Changelog; the project uses Semantic Versioning.

0.3.0Unreleased

Added

  • laya_watch — react to new rows instead of scanning old ones. laya_watch('tickets', 'the customer is threatening to leave', 'route_to_priority') arms a rule: a row trigger enqueues every new/changed row as jsonb (deduped by content, no model call in the write path), and laya_watch_tick() — from pg_cron, a worker, or by hand — judges the queue and runs action(payload jsonb) on every match. Actions are at-least-once, so make them idempotent. New helpers: laya_row / laya_row_prob, laya_watches(), laya_watch_queue(), laya_unwatch(), laya_watch_skip().
  • laya.state_mode — a native request format for the local Laya model. The default jev mode packs laya.batch_size rows into one shared state — what the cloud Jev model is built for. The local model cannot reliably separate rows in a shared state, so native sends one row per request: the row itself as the state, the condition in the question. laya.batch_size is ignored in native mode.
  • make install also installs the companion model server as a system service. It installs Ollaya — a single binary serving the Laya decision models — and starts it on http://127.0.0.1:11435: a systemd unit on Linux or a launchd agent on macOS, then pulls the laya router model (~1.5 GB, sha256-verified, resumable, non-fatal).

Changed

  • Default backend is now the local model server (Ollaya), pluggable to the cloud Jev model. Default laya.api_url is http://127.0.0.1:11435/v1/systemone and default laya.model is laya (Ollaya's router). Keep laya.concurrency low (2–4) — a loaded model runs one inference at a time.
  • The API key is optional. The extension only sends an Authorization header when a key is configured, so the default local server works with zero configuration. The server-side variable is OLLAYA_API_KEY.

Fixed

  • A Python syntax error (missing brace) in the 0.2.0 → 0.3.0 upgrade script.
0.2.02026-09-18

Measured against the live API on a 2,000-row table (~190 ms RTT): first run 8.5 s → 3.5 s, LIMIT 3 on a fresh condition 8.4 s → 0.6 s, 12% fewer input tokens, and answers that match single-row evaluation instead of drifting.

  • Streaming read-ahead — a table is no longer read whole before the first answer; it is streamed in physical order and each row is answered as soon as its batch returns. Memory is constant whatever the table size.
  • Persistent HTTPS connections — keep-alive across batches and statements (one TLS handshake per connection: 880 ms → 300 ms per request from Europe).
  • laya.batch_size 40 → 20 — 100% correct up to 20 rows per request, falling at 40 and 80. Cost: +4% input tokens.
  • laya.concurrency 6 → 16 and laya.timeout 90 → 30 s (waits now interruptible within 250 ms).
  • Added laya.keepalive, progress NOTICEs, Retry-After handling, and retries/in_flight/connections to laya_stats().
0.1.02026-09-17
  • laya(), laya_prob(), laya_score(), laya_score_norm(), laya_choice(), laya_confidence(), laya_eval().
  • Whole-table read-ahead with batched, concurrent requests and a per-session answer cache.
  • laya_stats() and laya_cache_clear(), plus the full settings set and spend guards.
  • Regression suite against a deterministic mock API; CI for PostgreSQL 14–17.
