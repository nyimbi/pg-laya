pg-laya docs
Local, plain-language predicates for PostgreSQL

Settings

Every setting is a plain PostgreSQL custom GUC under the laya. prefix, so all the usual scopes apply. Settings are read once per cache miss, so a change takes effect on the next uncached call.

sql
SET laya.threshold = 0.7;                       -- this session
SET LOCAL laya.max_rows_per_statement = 500;    -- this transaction
ALTER ROLE analyst SET laya.api_key = '...';    -- persistent for one role
ALTER DATABASE app SET laya.concurrency = 8;    -- persistent for one database
SHOW laya.batch_size;                           -- current value ('' → default applies)

All settings

SettingDefaultMeaning
laya.api_keyenv LAYA_API_KEY (optional)Bearer key for the endpoint. Not needed for the default local server; needed for the cloud Jev model or a key-protected server.
laya.modellayaModel name sent in every request. laya is Ollaya's router (English / multilingual per request); set laya:en / laya:multilingual to skip the router, or your endpoint's name elsewhere.
laya.threshold0.5Probability at which laya() returns true (the third argument overrides it).
laya.batch_size20Rows per API request. Accuracy drops measurably above ~20–25. Ignored in native state mode (always 1 row per request).
laya.state_modejevjev = shared state with rows[] (cloud Jev model); native = one row per request, state is the row itself. Use native with the local model server.
laya.concurrency16Parallel API requests (up to 2× queued). Keep it low (2–4) with the local server — a loaded model runs one inference at a time.
laya.max_prefetch_rows5000How far past a cache miss the read-ahead scans, and how many skipped rows it keeps (memory bound).
laya.noticesonNOTICE per finished request plus a per-table summary. Turn off in applications and tests.
laya.api_urlhttp://127.0.0.1:11435/v1/systemoneEndpoint — Ollaya's local server (default), laya[serve], the cloud Jev model, or a proxy/mock.
laya.timeout30Seconds per API request. Waits are interruptible: statement_timeout and cancel apply within 250 ms.
laya.keepalive600Seconds a pooled HTTPS connection may idle before reconnecting.
laya.max_rows_per_statement0 (off)Abort a statement that would send more rows than this to the API. A spend guard for shared servers.
laya.max_chars_per_statement0 (off)Same, for characters of row data. A guard for wide rows / token budget.

Recommended baseline for the local server

sql
ALTER DATABASE app SET laya.state_mode = 'native';              -- the format the local model is trained on
ALTER DATABASE app SET laya.concurrency = 4;                    -- it runs one inference at a time
ALTER DATABASE app SET laya.max_rows_per_statement = 5000;      -- spend guard
ALTER DATABASE app SET laya.max_chars_per_statement = 2000000;

If the server was installed on a non-default port, also run ALTER DATABASE app SET laya.api_url = 'http://127.0.0.1:<port>/v1/systemone';.

Recommended baseline for a shared server

sql
ALTER DATABASE app SET laya.max_rows_per_statement = 5000;
ALTER DATABASE app SET laya.max_chars_per_statement = 2000000;
ALTER ROLE analyst SET laya.api_key = '...';
ALTER ROLE analyst SET laya.model = 'laya:en';   -- skip the router: English checkpoint only

Guard errors read laya: this statement would send N rows to the API, above laya.max_rows_per_statement = M, so users know why and can add a filter or raise the limit with SET LOCAL for one statement.

Where the API key comes from

Precedence: laya.api_key GUC (any scope) → LAYA_API_KEY in the server process environment (TYPESAFE_API_KEY as a deprecated fallback). The client's shell does not count. Setting laya.api_key = '' disables the GUC and falls back to the environment. No key anywhere means no Authorization header — correct for the default local server, which runs unauthenticated.
