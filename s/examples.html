Examples

27 fully-coded, runnable examples: 12 business, 8 personal, 7 patterns. Each is a complete example.sql — it creates a small sample table, seeds realistic rows, and runs the query. Swap in your own table to use it for real.

▶

Run any of them straight from the repo: psql -d mydb -f examples/business/01-escalate-angry-tickets/example.sql. Prereq: the laya extension and the local model server (see Installation). Click a card to expand it.

Business · 12

01Escalate angry ticketsbusiness

Rank open tickets by how angry the customer sounds, so the most urgent surface first.

sql
SELECT id, subject,
       laya_prob(tickets, 'the customer is angry, frustrated, or about to give up') AS anger
FROM tickets WHERE status = 'open'
ORDER BY anger DESC LIMIT 5;

02Route tickets by teambusiness

Classify each ticket into the owning team and count the workload per team.

sql
SELECT laya_choice(tickets, 'which team should handle this ticket?',
                   ARRAY['billing','technical','security','sales']) AS team,
       count(*)
FROM tickets WHERE status = 'open'
GROUP BY 1 ORDER BY 2 DESC;

Count, per week, how many reviews the customer sounds frustrated in — a trend you can chart.

Patterns & techniques · 7

01Pick a thresholdpattern

Look at the probability distribution, inspect the ambiguous middle, then apply your cutoff — from the cache.

sql
SELECT width_bucket(laya_prob(reviews, 'the customer sounds frustrated or upset'), 0, 1, 10) AS bucket,
       count(*)
FROM reviews GROUP BY 1 ORDER BY 1;

Full file: examples/patterns/01-pick-a-threshold/example.sql

02Multi-label topicspattern

Tag a row with every topic it covers (not just one), using the full probability vector.

sql
SELECT id,
       laya_eval(messages, 'which topics does this message cover?', 'choice',
                 ARRAY['billing','technical','security','sales','praise']) -> 'probabilities' AS topics
FROM messages;

Full file: examples/patterns/02-multi-label-topics/example.sql

03Human in the looppattern

Auto-apply confident classifications, and queue the low-confidence ones for a person.

sql
UPDATE tickets t
SET team = laya_choice(t, 'which team should handle this ticket?', ARRAY['billing','technical','sales'])
WHERE laya_confidence(t, 'which team should handle this ticket?', 'choice',
                      ARRAY['billing','technical','sales']) >= 0.6;

Full file: examples/patterns/03-human-in-the-loop/example.sql

04Limit what the model seespattern

Put a view in front of the table so only the needed columns are judged — PII and blobs stay out.

sql
CREATE VIEW support_text AS SELECT id, message FROM support;
SELECT id,
       laya_choice(v, 'which team should handle this message?', ARRAY['billing','technical','account']) AS team
FROM support_text v;

05Manage costs on large tablespattern

Cheap SQL first, a bounded window, a spend guard, and laya_stats() to see what it cost.

sql
SET laya.max_rows_per_statement = 1000;
SELECT count(*) FILTER (WHERE laya(events, 'the customer is upset or about to cancel')) AS upset
FROM events
WHERE channel = 'email' AND created_at >= now() - interval '7 days';

06Compose with plain SQLpattern

Judge the side that carries the text, then join, CTE, CASE and aggregate with normal SQL.

sql
SELECT c.name, c.plan,
       laya(t, 'this customer is threatening to cancel or mentions a competitor') AS at_risk
FROM tickets t
JOIN customers c ON c.id = t.customer_id;

07React to new rowspattern

Arm a watch: a trigger enqueues new/changed rows (no model call in the write path), a scheduled tick judges them and runs your action on the matches.

sql
SELECT laya_watch('tickets', 'the customer is threatening to leave or cancel', 'route_to_priority');
INSERT INTO tickets VALUES (7, 'Greta', 'Keep this up and I am cancelling tomorrow.');
SELECT laya_watch_tick();  -- e.g. every minute via pg_cron
